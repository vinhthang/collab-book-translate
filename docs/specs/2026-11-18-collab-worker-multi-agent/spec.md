# Agent-Agnostic Role-Based Multi-Agent Collaboration & Worker CLI

- Feature ID: 2026-11-18-collab-worker-multi-agent
- Type: enhancement

## Problem and source intent

Turn `collab-book-translate` from a referee-only validator suite into a practical, agent-agnostic, role-based multi-agent book translation system on GitHub that works directly with two collaborator accounts (`vinhthang` and `1quachuoi9vang`, or external fork contributors) without any vendor-specific evaluator dependency or candidate window wait gate.

Authorizing user intent (2026-11-18, verbatim user prompts and `/grill-me` resolutions):

1. *"the goal is to have a multiple translate agents system that work, I build it, but never use it in real, so I am totally lost, is that 2 github account could work?"* -> Selected 2-account (`vinhthang` + `1quachuoi9vang`) parallel translation + cross-review workflow (`reviewer_login != pr_author_login`) with an Antigravity plugin skill and worker CLI helper.
2. *"remove that 24-hour gate"* and *"there is no 0h gate, and also remove this WorkBuddy - it is just other agent"* -> Eliminate the candidate window gate (`window_hours`, `[collab-window-start]`, `status:candidates`) and delete all vendor-specific `WorkBuddy` evaluator code and references across the repository.
3. *"maybe you should define some roles in the readme, and an agent could make merge request or comments based on defined roles"* and *"this is a collab between agents, so workbuddy is one of them, and workbuddy need to be register or check that github repository, right?"* -> Define explicit agent-agnostic roles (**Submitter & Human Approver**, **Translator**, **Reviewer**, **Coordinator**) in `README.md` with deterministic `scripts/collab_worker.py` commands so any AI agent can inspect the repository and execute a role using an authenticated GitHub account.

## Repository grounding

Inspected against `collab-book-translate` at commit `10ef139`:

- **Config & plugin manifest**: `scripts/collab_config.py` currently requires 14 keys including `window_hours` and `evaluation_engine` (`"workbuddy" | "cbc"`), and `plugin.json` contains non-standard top-level keys (`config`, `config_example`, `entrypoints`) rather than Antigravity's `plugin.json` schema (`name`, `displayName`, `description`, `version`, `repository`, `suggestedPrompts`).
- **Legacy vendor evaluator files**: `scripts/evaluators/workbuddy.py` and `scripts/evaluate_workbuddy.py` exist on disk and are referenced in `scripts/evaluators/__init__.py`, `scripts/evaluate.py`, `scripts/orchestrate_run.py`, `scripts/refine_chapter.py`, `scripts/evaluators/fallback.py`, `scripts/evaluators/scoring.py`, `scripts/utils/schemas.py`, `README.md`, and `tests/`.
- **Selection, verdict & sweep**: `scripts/collab_select.py` (`select_winning_pr`) enforces a `window_hours` wait timer (`[collab-window-start]`), and `scripts/collab_sweep.py` invokes `live_evaluate_pr` (`run_evaluation(..., engine=cfg.evaluation_engine)`) and lacks automatic GitHub label creation (`status:merged`, `status:not-selected`, `status:evaluating`, `book:<slug>`, `agent:<name>` are absent on `vinhthang/collab-book-translate`).
- **Seed git/worktree isolation**: `scripts/collab_seed.py` commits initial `runs/<slug>` (`source.txt`, `checklist.json`, `book_record.json`) with `push_origin=False` before branching `translate/<slug>-ch01-<bot>` in the primary working tree, risking multi-file PR diffs and `git pull --ff-only` merge conflicts.
- **Missing worker CLI & plugin customization**: `skills/`, `agents/`, and `scripts/collab_worker.py` do not yet exist in `collab-book-translate`.

## Non-goals

- **No candidate collection window or timed merge gate**: Passing reviewed PRs merge directly without waiting for a timer.
- **No built-in vendor CLI evaluator (`WorkBuddy` / `cbc`)**: Evaluation is performed through GitHub PR peer reviews by independent agents (`reviewer_login != pr_author_login`) combined with deterministic repository checks.
- **No separate GitHub account registration per AI tool**: Multiple AI agents share collaborator GitHub accounts (`vinhthang`, `1quachuoi9vang`) or external forks via per-command `GH_TOKEN` + `GIT_ASKPASS` isolation while declaring free-text `Engine/Model` provenance.
- **No GitHub Actions CI or webhook server**: Coordinator sweeps and worker commands run locally via CLI or Antigravity skills.

### REQ-032: Agent-agnostic peer-review and deterministic `score_of_record` evaluation

- Changes: [2026-11-18-collab-multi-agent-translation/REQ-024](../2026-11-18-collab-multi-agent-translation/spec.md#req-024-normative-evaluationresult-contract-normalized-verdict-threshold-and-per-reviewer-changes_requested-clearing)
- Source intent: Verbatim user decision (*"Peer-review + deterministic checks ... the opposite account's Reviewer subagent posts the 6-dimension scores + S-NNNN issues on the GitHub PR, and collab_sweep.py computes score_of_record from valid peer reviews + deterministic language/glossary/parity checks"*; *"remove this WorkBuddy - it is just other agent"*).
- Previous contract: `collab_sweep.py` invoked an internal `evaluation_engine` (`workbuddy`/`cbc`) binary after peer review to compute `EvaluationResult` and flagged $> 1.0$ divergence between reviewer and engine scores.
- Statement: WHEN a `ch02..chNN` translation PR at `<head_oid>` passes `REQ-021`/`REQ-023` pre-checks and has $\ge 1$ valid independent review (`REQ-022`, `review.author.login != pr.author.login`, anchored to `<head_oid>` whenever `commit_oid` is present on the review), THE coordinator (`evaluate_pr_from_reviews`) SHALL compute `EvaluationResult` deterministically without invoking any external LLM CLI:
  1. Take each distinct non-author reviewer's chronologically latest valid `REQ-022` review for `<head_oid>`, compute per-dimension arithmetic means across reviewers for `fidelity`, `fluency`, `terminology`, `register`, `structure`, and `completeness`, and compute `weighted_total` (`score_of_record`) via `compute_weighted_total`.
  2. Extract severity-tagged issues (`[critical]`, `[major]`, `[minor]`) from those review bodies, run `enforce_language_detection` on `translation.xml` (plus `anti_convert` lexical checks when `source_lang == "zh"`), and set `fallback_unverified = False`.
  3. Normalize `verdict` against `effective_threshold` (`3.5` for `"fiction" | "literary"`, `4.0` otherwise): `"PASS"` when `score_of_record >= effective_threshold` and `critical_count == 0`, else `"FAIL"` (`Reassign` when `score_of_record < 2.5`, otherwise `Revise` subject to `REQ-027`; un-cleared `CHANGES_REQUESTED` reviews per `REQ-024` also route to `Revise`).
- AC-032-1 — Success: Given $\ge 1$ commit-matching valid non-author `REQ-022` review with weighted score $\ge effective\_threshold$, zero `[critical]` issues, clean Vietnamese language detection (and clean `anti_convert` on `zh`), and zero blocking `CHANGES_REQUESTED` reviews, `evaluate_pr_from_reviews` returns `verdict == "PASS"` with `fallback_unverified == False` and exact weighted `score_of_record`.
- AC-032-2 — Boundary/failure: IF all reviews on the PR are authored by `pr.author.login` or target stale commits (`commit_oid != <head_oid>`), THEN THE PR SHALL remain in `NeedsReview` (`status:needs-review`); IF `translation.xml` fails `enforce_language_detection`, contains `[critical]` reviewer issues, has `score_of_record < effective_threshold`, or has an un-cleared `CHANGES_REQUESTED` review, THEN THE PR SHALL route to `Revise` (`status:revise`, or `status:reassign` when `score_of_record < 2.5` or revision cap is exceeded).

### REQ-033: Direct post-review selection and merge without a candidate window gate

- Changes: [2026-11-18-collab-multi-agent-translation/REQ-026](../2026-11-18-collab-multi-agent-translation/spec.md#req-026-cohort-competing-pr-window-severity-tie-breaks-and-bounded-48-h-starved-chapter-fallback), [2026-11-18-collab-multi-agent-translation/REQ-027](../2026-11-18-collab-multi-agent-translation/spec.md#req-027-inlined-state-machine-transition-guards-label-reconciliation-and-deterministic-sha-keyed-revision-cap)
- Source intent: Verbatim user prompts (*"remove that 24-hour gate"*; *"there is no 0h gate"*).
- Previous contract: Entering `Candidates` posted `[collab-window-start epoch=...]` on the chapter issue and blocked selection until `window_hours` elapsed.
- Statement: WHEN a coordinator sweep evaluates all open translation PRs for an open chapter issue in Phase `(b)` and $\ge 1$ eligible passing PR exists (zero blocking `CHANGES_REQUESTED` reviews and zero unresolved threads), `select_winning_pr(candidates)` in Phase `(c)` SHALL immediately select the highest-ranked passing PR by `(-score_of_record, major_issue_count, minor_issue_count, pr_number)` without posting `[collab-window-start]` or waiting on any timer, merge the winning PR (`--match-head-commit <winner_head_oid>`), close any simultaneously open non-selected PRs as `status:not-selected` with score comparison feedback, and transition the chapter issue directly from `Open` (`status:open`) to `Done` (`status:done`), while preserving `REQ-026`'s 48 h starved-chapter fallback when an `Open` chapter has zero open PRs for `fallback_hours`.
- AC-033-1 — Success: In a single sweep, a single passing reviewed PR merges immediately and closes the chapter issue as `status:done` with zero `[collab-window-start]` comments; when two competing PRs on the same chapter both have valid peer reviews in the sweep, both are evaluated in Phase `(b)` and the higher-ranked PR merges immediately in Phase `(c)` while the runner-up closes as `status:not-selected`.
- AC-033-2 — Boundary/failure: IF passing PRs tie on `score_of_record`, THEN `select_winning_pr` SHALL break ties deterministically by `(major_issue_count, minor_issue_count, pr_number)`; IF zero passing eligible PRs exist on the chapter, THEN no PR SHALL merge and the chapter issue SHALL remain `status:open`.

### REQ-035: Role-aware multi-account worker CLI (`scripts/collab_worker.py`) with isolated Git/GitHub auth

- Source intent: Verbatim user decisions (2-account `vinhthang` + `1quachuoi9vang` workflow; role-based PR and review actions by any AI agent without mutating global `gh auth`).
- Statement: THE repository SHALL provide `scripts/collab_worker.py` authenticating every `gh` and HTTPS `git` subprocess strictly as `--gh-user <login>` via `gh auth token -u <login>` in `GH_TOKEN` plus an ephemeral `GIT_ASKPASS` script (never invoking `gh auth switch` and never exposing tokens on process command-line arguments), supporting five deterministic subcommands:
  1. `list-tasks --role <translator|reviewer|all> --gh-user <login> [--book-slug <slug>] [--workers <csv>] [--mode sharded|compete]`: outputs JSON listing open `ch02..chNN` issues assigned to `<login>` (sharded deterministically across `--workers` by chapter index in `sharded` mode, or all open issues in `compete` mode), open `status:revise` PRs authored by `<login>` with parsed defect comments, and open translation PRs authored by *other* logins (`author != <login>`) needing a commit-fresh `REQ-022` review from `<login>`.
  2. `submit-book --gh-user <login> --slug <slug> --source-file <path> --title <str> --author <str> --source-lang <en|zh> [--target-lang vi] --license <str> --license-url <https-url> [--genre <str>]`: runs `validate_submission_pr` locally before pushing, creates branch `book/<slug>` in an ephemeral `.worktrees/` checkout, commits & pushes `books/<slug>/manifest.json` and `books/<slug>/source/<filename>`, and opens the book submission PR.
  3. `approve-intake --gh-user <login> --pr <num> [--allow-warn]`: verifies `<login> == cfg.human_approver` and that `bot_login` posted `[collab-prescreen sha=<head_oid> status=PASS]` (or `WARN` when `--allow-warn` is set) on the PR's current `<head_oid>`, then posts `/approve-intake <head_oid>`.
  4. `submit-translation --gh-user <login> --book-slug <slug> --chapter <chNN> --translation-file <xml> [--additions-file <json>] --engine-model <str> [--agent-name <str>] [--claim]`: runs `validate_translation_pr` locally against `main`'s `manifest.json`, `book_record.json`, `chNN/source.txt`, and open chapter issue before pushing; optionally posts `/claim`; commits & pushes `translate/<slug>-<chNN>-<login>` from an ephemeral `.worktrees/` checkout (cleaning up the worktree on exit); and creates or updates the PR with compliant metadata and `agent:<agent-name>` label.
  5. `submit-review --gh-user <login> --pr <num> --review-file <md> [--event COMMENT|APPROVE|REQUEST_CHANGES]`: fetches the PR's author and `<head_oid>`, runs `validate_review` locally (`<login> != pr_author`, 6 dimensions in `[1.0, 5.0]`, `S-NNNN` segment note, zero prompt injection), and posts the GitHub PR review as `<login>`.
- AC-035-1 — Success: Concurrent or sequential `collab_worker.py` invocations for `--gh-user vinhthang` and `--gh-user 1quachuoi9vang` list role-filtered tasks accurately, open/update PRs from cleaned-up `.worktrees/` directories, post valid cross-account reviews, leave global `gh auth status` active account unchanged, and expose zero tokens in command-line arguments.
- AC-035-2 — Boundary/failure: IF local pre-flight validation fails in `submit-book` (`validate_submission_pr`), `approve-intake` (missing/failed prescreen or wrong approver), `submit-translation` (`validate_translation_pr`), or `submit-review` (`validate_review`, including self-review `<login> == pr_author`), THEN `collab_worker.py` SHALL exit non-zero with structured JSON defect details BEFORE pushing any branch, opening any PR, or posting any review.
